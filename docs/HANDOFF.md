# 交付范围与差异

本仓库将四模块视为一个系统；不重写为一个进程。`module-two-candidate` 的历史目录名保留，实际服务承载正式 V20/V10，不代表它使用旧候选规则。

## 已包含

运行代码及静态页面；第一、第二模块的递归规则依赖和 Inter 字体文件；第三模块研究引用所需的 JSON 和案例素材；第四模块材质参考资产；冻结清单；UI1 补丁记录；Docker、Compose、HTTPS 网关、全系统预算和用量记录；离线测试、Linux CI、部署维护说明。

Inter 原始发行压缩包与已解压字体重复，部署副本排除发行 ZIP，保留字体及授权文件。生产镜像无需装 Node.js：浏览器原生执行现有 JS。历史辅助脚本不是正式启动入口。

## 不作为运行依赖复制的资料

旧任务、用户上传图、已生成图片、旧预算台账、临时单日不限额授权、日志和缓存均保留在原机器，不放入新部署数据卷。尤其一份历史接口响应命中了密钥格式，不可原样提交。新站初始历史为空，不影响规则运行。若需迁移历史，先另做脱敏、版本兼容核对与独立备份。

原项目的研究交付物、旧实验和长篇交接说明作为补充归档交付；它们不是部署启动时的必需目录。完整原目录路径清单见 original-inventory.json，`included=false` 不等于删除原文件。

## 云端适配

- 首页面的第三/第四模块链接改成同域路径；独立模块 API 与资源请求增加对应前缀。
- 后端保持仅监听容器内 loopback，不取消原来源校验。Nginx 先验证外部 Origin，再转发为对应本地 Host/Origin；Caddy 提供 HTTPS 和共用账号认证。
- Mac `sips` 的读取校验替换为 Pillow 解码验证，输入图片不重采样、不改色、不改写字节。异常尺寸/损坏图片仍拒绝。
- “保留原文”本地 OCR 从 macOS Vision 换成 Linux Tesseract（英语）。两种引擎不能保证识别结果逐字相同，低置信度仍沿用原规则要求人工核对/填入原文。该模式需真实素材重点验收；其他生图规则不因此放宽。
- 不调用 Mac 钥匙串或桌面启动器；使用只读密钥文件经 stdin 传给三个服务。
- 在真实模型传输之前执行共享 SQLite 原子预算预留。模型请求正文、型号、生成参数不因计量改变。
- 第三模块原本的本地日预算在云端配置启用时由全系统日/月预算接管，测试环境保留原冻结逻辑用于回归。旧日不限额文件不会被带入。
- 运行源码的版本指纹会因适配改变，生图规则版本仍为 V20/V10/E31/V35；不能把源码指纹不同误判为规则升级。

## 现阶段边界

GitHub CI 使用假密钥，只验证构建、服务、上传准备和规则/计量；不会验证 Gemini 计费账户、模型可用性或图片效果。真实出图需在目标服务器完成。当前数据是单机文件和 SQLite，不支持把 app 扩成多个副本；不要直接增加 replicas。

服务重启会将未完成任务标为停止或暂停，不自动重发。用户先查看历史，确认状态后显式重试。共用账号不包含个人归属、角色权限或跨用户数据隔离。

## 原始文件留档

`baseline/original-adapted-files/` 保存所有被部署适配修改的文件在整理前的原始内容；其余未修改文件可直接按 `source-sha256.json` 校验。这样可以复核每一处迁移差异，无需依赖原电脑。
